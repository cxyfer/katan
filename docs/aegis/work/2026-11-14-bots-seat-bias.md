# New Shores 座位勝率偏差與 standard 對 naive 勝率拆解（#174、#135）：量測報告

本檔是諮詢性的工作紀錄，只量測、不改任何 bot 決策或規則。對應 issue：[#174](https://github.com/cxyfer/katan/issues/174)（3 人 sf-ck 全 standard 的座位勝率偏差）與 [#135](https://github.com/cxyfer/katan/issues/135) 的「對局拆解」項（standard 在 `sf-new-shores-2025` 3–4 人對 naive 未達 Q3 目標）。背景見 [SF+CK 工作紀錄](2026-11-12-bots-seafarers-cities-knights.md)「已知限制」與 [SF 計畫 §6.3](../plans/2026-11-04-bots-seafarers.md)。

## 結論

1. **座位勝率的差距主要跟著各座位拿到的開局頂點走；回合順序的效應不大，但這組資料量不出它的上限。** 3p／4p New Shores 的地圖固定，bot 的開局又是確定性的（同一策略、同一座位、500 局開局完全相同），所以每個座位的開局品質固定且差距極大。把開局頂點在座位間輪換（拉丁方陣，每格 500 局）後，全 standard 的勝率跟著開局走：開局邊際的最大差距是 37–61 pp（1.85% 到 67.6%；以種子為 cluster 的 bootstrap 95% 區間下界都 ≥ 32 pp）。座位邊際則落在公平份額附近（3p 31.7–35.0%、4p 24.1–26.4%），六組全 standard 的最大兩兩座位差距是 0.7–2.7 pp。強度的界線：這個「兩兩座位差距」的**同時 95% 區間**（cluster bootstrap，見〈方法〉）半寬約 ±3.5–4.7 pp，所以兩兩差距的 95% 上界是 5.3–7.1 pp：資料不能排除 standard 在固定地圖上有 5–7 pp 的回合順序效應，也不能證明它是零（單一座位勝率的 Wilson 區間約 ±2.4 pp，那不是座位差距的區間，不能拿來界定上限）。能說的只有相對大小：各組態的開局邊際差距（區間下界 ≥ 32 pp）約是座位差距上界（≤ 7.1 pp）的 5 倍以上。
2. **回合順序的效應不是零，但這份資料量不準它的大小。** 隨機地圖的 `ck-2025` 是純回合順序的對照（每局獨立，直接對局重抽）：全 standard 4p 的座位勝率是 29.8／20.2／25.8／24.2%，最大兩兩差距 9.6 pp，同時 95% 區間 1.4–17.8 pp（只勉強排除 0；卡方 p = 0.024）；3p 是 35.2／36.0／28.8%，差距 7.2 pp，區間 −1.4–15.8 pp，不能排除 0。全 easy 在 `ck-2025` 3p 為 34.4／24.8／40.8%，差距 16.0 pp，區間 7.6–24.4 pp，明確非零；4p 差距 9.2 pp，區間 1.0–17.4 pp。固定地圖的拉丁方陣中，easy／naive 的座位邊際差距是 5.5–12.0 pp（最大是 sf-ck 3p easy 的 39.6／32.8／27.6%），六組的同時區間都不含 0（下界 0.3–7.5 pp；最小的 sf 4p naive 只有 0.3 pp，而且它只有 245 局可用，見第 3 節），但方向不一致（sf 3p easy 反而座位 2 最高）。這份報告做了很多比較，`ck-2025` 4p standard 的下界只比 0 多 1.4 pp，只能算「有跡象」；所以較穩當的說法是：easy／naive 有可辨識的座位差距（約 5–12 pp，固定地圖上它與開局位置混在一起），standard 的座位差距在 0 到十幾 pp 之間，無法更精確；兩者合起來，座位的效應仍遠小於開局位置的 37–61 pp。
3. **這個偏差同時是策略問題：** 每個座位的開局是 bot 的 setup 演算法在固定地圖上貪心選出來的，沒有「對手會拿走什麼」的前瞻，也沒有「兩顆聚落合起來要湊齊 grain／ore」的要求。4p 座位 3 的開局 27／67 完全沒有 grain，不論換到哪個座位都只贏約 1.85%（sf）／5.0%（sf-ck）；反事實實驗把座位 3 換成帶 grain 的開局，勝率從 1.2% 升到 22.2–45.4%。所以結論不是「地圖不公平、記下來就好」，而是**值得開 setup 策略的後續 issue**（見〈建議〉）。
4. **#135：standard 對 naive 的 Q3 落差，大部分跟 standard 在 setup 階段的決策有關；這組資料量不出島嶼／造船投資本身的報酬。** 最乾淨的對照是 `--setup-from naive`：只把 standard 座位的 setup 階段決策（聚落、道路、船）換成 naive 的決定，兩邊都自選、不用腳本頂點。3p 的 standard 勝率從 23.7%（1500 局，bench 的原條件）升到 40.5%（逐局配對差 +16.9 pp，95% 區間 +13.8～+19.9；Q3 目標 ≥ 43.3%，區間上界 43.0% 仍略低）；4p 從 32.7% 升到 36.6%（+3.9 pp，+0.5～+7.3；目標 ≥ 35%，達到）。換掉 setup 之後，每一局的各座位開局都與全 naive 的開局完全相同（3p、4p 各 1500／1500 局），所以差異來自 standard 在 setup 階段做的選擇（包含它的選擇對留給 naive 的頂點的影響）；這個對照分不出是聚落、道路還是船的哪一個決定造成，也沒有檢驗 setup 改成哪一種會更好。換成同一個 setup 後，standard 的勝率仍高於公平份額（3p 40.5% 對 33.3%、4p 36.6% 對 25%），可見 standard 在這個開局位置上沒有輸給 naive。**用腳本頂點的對照不能單獨解讀**：兩邊都固定（`stdopen`／`naiveopen`）時 3p 是 42.9%／42.1%、4p 是 47.5%／36.1%；只固定 standard（naive 自選）時 3p 21.7%／26.5%、4p 38.8%／33.3%，但 standard 的腳本頂點在 55–100% 的座位局被 naive 先占走而退回自選，幾乎沒有真正套用；只固定 naive（standard 自選）時 3p 50.5%／47.1%、4p 43.0%／46.2%，其中 naive 也有 33–44% 的座位局落空。腳本頂點會同時改變對手的開局，所以不能由此歸因於哪一方的開局。這些對照比較的都是整套策略，**回答不了「船／島投資本身的報酬」**：島嶼加分與造船數是對局的結果變數（贏的人有更多機會累積），而且沒有「關閉島嶼計畫的 standard」這個對照組（要改 `src`，本任務不做）；報告裡投入與勝率的對照表（例如小島加分 2 次以上勝率 59.3%／71.4%，不到 2 次 20.4%／25.4%）都是觀察性資料，不能解讀為投資的因果報酬。換成 naive 的 setup 後 standard 的小島加分（3p 1.07、4p 0.66 次）與付費船（2.54、1.77 艘）都少於原條件（1.58、1.48 次；2.93、4.03 艘），勝率卻較高，但這同時改了開局位置，不能解讀成投資多寡的因果。因此 #135 的假說「船／島投資在 3–4 人回本不足」既沒有被證實、也沒有被推翻。
5. **#177（#171 的修正）不改變座位偏差。** 3p 全 standard 的座位勝率在修正前後幾乎相同（sf 19.0／57.2／23.8 → 20.2／55.6／24.2%，sf-ck 65.8／30.2／4.0 → 66.6／27.8／5.6%），拉丁方陣的結論不變；它讓 sf-ck 3p 1 standard vs 2 naive 的 6 局看門狗歸零（494／500 → 500／500）。有一個需要 #177 作者確認的副作用：在兩邊都固定開局的 3p standard 對 naive 局中，standard 坐在全內陸開局 63／57 時勝率從 72.6% 降到 61.6%（各 500 局），其他開局不變（見〈#171／#177 前後對照〉）。

## 方法

- **工具**：新增 `packages/bots/bench/survey.ts`（啟動器 `survey.mjs`，仿 `run.mjs`）。對局流程與 `bench/run.ts` 完全相同（同一個 `runBotGame`、仿 BotDriver 模式與看門狗、種子 `10000 + 局號`、focus 依局數輪換座位），所以不改任何既有 bench 的輸出；對同一組態，`survey` 的 focus 勝率與 `bench` 一致。
- **每局記錄**（逐座位）：勝負、終局分數、開局頂點與其點數（pips）、付費／免費造船、小島加分、聚落、城市、道路、發展卡、玩家與銀行交易、產出張數、回合數、最長道路／最大騎士團。來源是 `state.stats` 與 rules 事件。
- **統計（逐格）**：座位勝率附 Wilson 95% 信賴區間；座位均勻性用卡方（自由度 = 人數 − 1）。每格 500 局；沒有做多重比較校正。這些是「單一座位的勝率」的區間與逐局獨立假設下的 p 值，**不是座位間差距的區間**；拉丁方陣各位移共用同一批種子，所以位移之間也不獨立。拉丁方陣的 p 值只當描述用，座位對比的不確定性看下一項。
- **統計（座位對比，cluster bootstrap）**：以種子（局號）為 cluster 重抽（B = 10000；每個組態各用獨立、固定的亂數種子）：重抽到某局號時，把它在所有位移的結果一起抽，保留共用種子造成的相關。報告三個量：(a) 各座位邊際勝率的 95% 百分位區間；(b) **所有兩兩座位差距的同時 95% 區間**，半寬 = 重抽後 `max(i<j) |c*_ij − c_ij|` 的 95 百分位（同時涵蓋全部座位對，包含「事後挑最大那一對」，不需再校正多重比較），上界 = 觀察到的最大兩兩差距 + 半寬；(c) 開局邊際最大差距（range）的百分位區間。`ck-2025`（沒有位移、每局獨立）直接對局重抽。分析腳本在 repo 外的 scratch（`bootstrap.py`，不提交），輸入是 `--jsonl` 的逐局輸出；結果見第 3 節的第二張表。
- **拉丁方陣只用共同終局的局號、並檢查分片**：`--latin` 只保留在每個位移（0..人數−1）都有記錄、而且都終局的局號（交集），所以每個種子在每一種「座位 × 開局」排列各出現一次，邊際不會混入種子本身的結果；被剔除的局數逐位移回報（stderr 警告與輸出表頭）。位移編號重複、缺漏或超出範圍、局號重複、空分片、局數與 meta 不符、局號超出宣告範圍、種子不是 `10000 + 局號`、組態（profile、人數、角色、開局、`--script-roles`、`--setup-from`）不一致，都會被拒絕；`--merge` 池化的位移不完整或各位移局數不同時警告。本報告所有拉丁方陣、bootstrap 與 §5.2 的池化數字都用同一個規則重算：只有 4p 全 naive（每個位移保留 245／500 局，其餘位移各有 11–23% 的局被看門狗截斷）、3p 全 naive（496）、sf-ck 3p 全 easy（`2c9bd75`，499）、4p `naiveopen` 兩邊都固定（498）與只固定 standard（499）有剔除，其餘全部保留。只保留「在每種排列都終局」的局，可能偏向較快結束的局（倖存者偏差），所以 4p 全 naive 的結果只有參考價值。
- **座位 vs 位置（`--openings`／`--shift`）**：不改 rules，而是在 bot 的聚落決策外包一層，把座位 s 的兩個聚落頂點換成「第 (s + k) % 人數 份開局」（道路與其後策略不變；腳本頂點不合法時退回 bot 自己的選擇並記 `scriptMiss`）。k 取 0..人數−1 共跑 人數 組，每個座位輪過每份開局（拉丁方陣）：座位邊際平均掉開局，只剩回合順序；開局邊際平均掉座位，只剩位置。`--shift 0` 重現基線已驗證：sf 3p 全 standard 500 局的勝者逐局相同、`scriptMiss` 為 0。**不用「rules scratch patch 輪換起始玩家」**：全同策略時，輪換起始玩家只是座位重新標號，分不出位置與順序，腳本開局的分離更直接，也不必動 rules。
- **#135 的對照實驗**（細節與限制見 §5.2）：(a) 兩邊都固定：同一組腳本聚落頂點套在所有座位（standard 輪過每個座位），standard 與 naive 在每個座位上拿到同樣的開局頂點；naive 的頂點也被改成腳本的，setup 的道路與船仍由各自策略選，所以不能說成純粹的「非 setup 策略」。開局組有兩份：`stdopen`（全 standard 時各座位的開局）與 `naiveopen`（全 naive 時各座位的開局）。(b) 只固定一方（`--script-roles`）：另一方自選，腳本頂點被占走時退回自選並記為落空，落空率很高，不是乾淨的單邊干預。(c) **`--setup-from naive`**：`standard` 座位的所有 `setup.*` 指令（聚落、道路、船）取 naive 的決定，其餘階段仍是 standard；不用腳本頂點，也不會有頂點衝突，結果的開局與全 naive 完全相同。原條件與 (c) 用相同種子與局號，另以逐局配對差（以局為單位 bootstrap，B = 4000，固定亂數種子；只用兩個條件都終局的局號）估計差距的區間。
- **地圖固定的證據**：3p／4p 的 `sf-new-shores-2025`、`sf-ck-new-shores-2025` 在種子 10000–10039 的地形與數字完全相同（`newShoresLayout` 對 3、4 人用 `fixedLayout`）；5–6 人的主島是 `pairedLayout` 洗牌的，本報告沒有量測。`ck-2025` 的地圖每局隨機，當作純回合順序的對照組。
- **版本與環境**：基線（§1）、拉丁方陣位移（§3）與反事實在 `885644a`（v0.4.3-rc.1）；3p 的修正後數字在 PR #177 的 head `2c9bd75`（survey 檔案以未提交的拷貝疊上，不 commit 到 #177）。4p 與 `ck-2025` 沿用 `885644a`（#177 說明 4p 不受影響）。§5.2 的腳本對照在 `9534073`（release/v0.4.3 `0f467b8` 之上，含 #176、#177、#178），`--setup-from` 對照在 `cdbcff9`（只多了 bench 的 survey 選項）。大量運算在 Instabox 跑（最多 3 個程序）；原始逐局 jsonl 與腳本在 repo 外的 scratch（不提交）。

重現（在 `packages/bots`；`$P` 是 profile）：

```bash
node bench/survey.mjs 500 --profile $P --players 3 --roles standard            # 全 standard；easy、naive 同理
node bench/survey.mjs 500 --profile $P --players 3 --roles standard:naive      # 1 standard vs 2 naive；standard:easy 同理
node bench/survey.mjs 500 --profile $P --players 3 --roles standard --openings 35/78,76/63,37/57 --shift 1 --jsonl s1.jsonl
node bench/survey.mjs 500 --profile $P --players 3 --roles standard:naive --setup-from naive   # standard 的 setup 換成 naive 的決定（與 --openings 互斥）
node bench/survey.mjs 500 --profile $P --players 3 --roles standard:naive --openings 35/78,76/63,37/57 --shift 1 --script-roles standard   # 只腳本化 standard
node bench/survey.mjs --latin s0.jsonl s1.jsonl s2.jsonl                       # 座位 × 開局矩陣與兩個邊際
node bench/survey.mjs --merge a.jsonl b.jsonl                                  # 合併分片（位移不同則池化）
```

`--from <局號>` 可把 500 局切成分片平行跑。

### 5.2 對照實驗：固定誰的開局，或把 standard 的 setup 換成 naive 的

先講每種對照到底改了什麼，因為它們能回答的問題不同。腳本頂點（`--openings`）只換**聚落頂點**，setup 的道路與船仍由各自的策略選；而且腳本頂點會同時改動對手的開局，不是只動一方。

### 5.3 這組資料能回答與不能回答的

**能回答：**

1. 把 standard 的 setup 階段決策換成 naive 的之後（開局位置與全 naive 相同），standard 的勝率從 23.7% 升到 40.5%（3p）、從 32.7% 升到 36.6%（4p）。所以 Q3 落差的大部分（3p）與全部（4p，點估計）跟 standard 在 setup 階段的決定有關。（`--setup-from naive` 換的是整個 setup，包含它對留給 naive 的頂點的影響。）
2. 在同一個開局位置上，standard 之後的整體打法沒有輸給 naive（3p 40.5%、4p 36.6%，高於公平份額 33.3%、25%）。

**不能回答：**

1. **是 standard 的哪一個 setup 決定造成的**：聚落頂點、道路與船沒有分開換。腳本頂點的對照（只固定 standard 或只固定 naive）因為頂點衝突與對手的連動，也沒有補上這個缺口。
2. **該改成什麼樣的 setup 最好**：只驗證了「換成 naive 的」會改善，沒有驗證任何新的 setup；`--setup-from naive` 的增益只適用於這個開局位置（4p 的 +3.9 pp 還是座位間的重新分配）。
3. **「船／島投資在 3–4 人回本不足」的假說**：這些實驗比較的都是整套策略，沒有關閉島嶼計畫的 standard 對照組（要改 `src`，本任務不做）；島嶼加分與造船數是結果變數，不是被指派的處理。要檢驗這個假說，需要在 `src` 加一個可關閉島嶼計畫的開關，再用同一個開局位置（例如 `--setup-from naive`）比較開／關。
4. 「naive 的開局一律比較好」並不成立：兩邊都固定、4p 時 standard 套用 naive 的開局組只有 36.1%，低於套用自己的開局組的 47.5%，開局與策略有交互作用。

## 建議

**對 #174（座位偏差）**：差距主要來自「固定地圖上的確定性開局」（開局邊際差距 37–61 pp，bootstrap 區間下界 ≥ 32 pp）。回合順序的效應在 standard 上與 0 無法區分，但兩兩座位差距的 95% 上界仍有 5–7 pp（easy／naive 則有可辨識的 5–12 pp），所以本報告沒有「回合順序無關」的結論，只有「遠小於開局位置」。隨機化固定地圖的座位順序只能處理較小的那一塊，不是主要槓桿；主要槓桿在 bot 的 setup。建議開後續 issue（草稿如下），不在 #174 裡調參。

- 觀察到的差異（**假說**，尚未用對照證實哪一項是因）：base 的 `setupSpotScore` 在第 2 輪對「合起來沒有 grain」只扣 1.5（沒有 lumber／brick 各扣 3），27／67 的組合因此被接受；`islandSetupBonus` 把能登島的沿海點加分，4p 四個座位第一輪都選 8–9 點的沿海，naive 只用 `setupSpotScore`，選 10–12 點的內陸。`--setup-from naive` 同時換掉聚落、道路與船，所以不能把改善歸因於 `islandSetupBonus` 或第 2 輪的缺 grain 扣分。

**建議的評分方向**（假說，逐項用下列驗收指令檢驗，不要一次全上；先用 `--setup-from naive` 的結果當作已知可達的參考點）

1. 第 2 輪在 SF module 內對兩顆聚落合起來缺 grain（其次 ore）加重扣分（相對 base 的 −1.5），並讓 sf-ck 的 `touchesOreOrGrain` 篩選改成要求「合起來有 grain」。
2. 降低 `BONUS_WEIGHT`，或只在第 2 輪才計 `islandSetupBonus`，使登島加權不會壓過明顯更高產量的內陸點。
3. （選配）第 1 輪加一步前瞻：候選點的價值加上「剩下的合法點裡、尚未被對手占掉的最佳第 2 輪配對」的分數。

**驗收**（在 `packages/bots`，`P` 是 profile `sf-new-shores-2025` 與 `sf-ck-new-shores-2025`）

- 未控制開局（bench 的原條件）：`pnpm --filter @catan/bots bench 500 --profile $P` 的 `3p／4p 1 standard vs naive` 列，目標 3p ≥ 43.3%、4p ≥ 35%；要看座位分布與更窄的區間時用 `node bench/survey.mjs 1500 --profile $P --players 3 --roles standard:naive`（現況 sf 3p 23.7%、4p 32.7%）。
- 與「standard 的 setup 換成 naive 的」比較：`node bench/survey.mjs 1500 --profile $P --players 3 --roles standard:naive --setup-from naive`（現況 sf 3p 40.5%、4p 36.6%）；新 setup 若比它差，代表改動沒有勝過現有的 naive setup，需要重新檢視。
- 全 standard 的公平性：`node bench/survey.mjs 500 --profile $P --players 4 --roles standard`，目標每個座位離公平份額不超過約 10 pp（現況 4p sf 座位 3 為 1.2%、sf-ck 為 4.0%），並用 `--latin`（`--openings` 取新的各座位開局，`--shift` 0..人數−1）確認開局邊際收斂。注意 naive 的 setup 在這個公平性上也有偏差（全 naive 3p 座位 31.7／20.8／47.5%），所以只換成 naive 的 setup 解不了 #174。
- 兩邊都固定開局的回歸檢查（確認 setup 以外的打法沒有退步）：`node bench/survey.mjs 500 --profile sf-new-shores-2025 --players 3 --roles standard:naive --openings 35/78,76/63,37/57 --shift k`（k = 0、1、2；4p 用 `78/84,92/44,27/67,29/76` 與 k = 0..3），用 `--merge` 池化；數字應維持在現況附近（`9534073`：3p 42.9%、4p 47.5%）。這組腳本頂點也會改動 naive 的開局，只能當回歸檢查，不能用來歸因。
- 另外：`BOTS_SEEDS=10 pnpm verify`（Q1／Q2）與 Q3 bench 重跑；base 與 sf、ck 的 golden 雜湊不變（只動 SF 的 module）。

**預期效果**（保守）

- 已知有一個 setup（naive 的）能讓 3p standard 對 naive 到 40.5%、4p 到 36.6%（離 Q3 目標：3p 差 2.8 pp、4p 達到），所以「不改任何島嶼／造船策略、只改 setup」有機會讓 Q3 接近達標；這是參考點，不是保證：新的 setup 會產生自己的開局，可能更好也可能更差，而且 `--setup-from naive` 的增益只適用於那個開局位置（4p 的 +3.9 pp 是座位間的重新分配）。
- 目標是全 standard 的最差座位（4p sf 座位 3 的 1.2%、sf-ck 的 4.0%、3p sf-ck 座位 3 的 4.0%）回到接近公平份額；這與 Q3 是兩個獨立的驗收，兩個都要看。

## 未驗證範圍與限制

- 5–6 人（主島變動）、E&P、T&B 沒有量測；`ck-2025` 的修正後數字沒有重跑（#177 不影響 C&K）；4p 沒有在 `2c9bd75` 上重跑（依 #177 的說明）。`--setup-from naive` 只在 `sf-new-shores-2025` 的 3p、4p 做，`sf-ck-new-shores-2025` 沒有做（該 profile 的 1 standard vs naive 原本就是 83–100% 勝率，沒有 Q3 缺口）。
- 種子只有 10000–10499（拉丁方陣各位移共用同一批種子，位移之間不是獨立樣本；修正前後也共用種子）；§5.2 的對照用 10000–11499（原條件與 `--setup-from` 的配對用同一批）。
- 投入與勝率是觀察性資料：造船數與小島加分是對局結果，勝者更容易累積，不能解讀為投資的因果報酬；沒有「關掉島嶼計畫」的對照組，所以 #135 的假說沒有被檢驗（既未證實也未推翻）。
- `--setup-from naive` 單獨改變 standard 的 setup 決策，但整個 setup（聚落、道路、船）一起換，也一併改變留給 naive 的頂點；分不出是哪一個決定、也沒有測試任何新的 setup。腳本頂點的對照（只固定 standard、只固定 naive、兩邊都固定）都會同時改動對手的開局，落空率高時不是單邊干預，只能當描述，不能歸因。
- 反事實只做了 4p 座位 3 的三個候選，且其餘座位因頂點衝突改走自己的選擇（`scriptMiss` 在 jsonl），不是乾淨的單座位干預。
- 兩邊都固定的結果依開局組而變（4p 的 stdopen 47.5% 對 naiveopen 36.1%）；兩組都不是「最公平」的開局，只是兩個有代表性的組合。
- easy／naive 的拉丁方陣套用 standard 的開局，兩者本身的 setup 不在這組開局內時，結果解讀為「位置的影響」而非「它們會怎麼選」。
- 逐格的 Wilson 區間與卡方 p 值視每局獨立，多重比較沒有校正；座位對比改用以種子為 cluster 的 bootstrap（同時區間，見〈方法〉）。63／57 的 11 pp 退步是在數個開局中挑出的一格，需要重跑確認。
- C&K 系列的全 naive 在 3p／4p 幾乎都被看門狗截斷（已知限制），沒有該組的座位勝率。
- 4p 全 naive 的拉丁方陣，每個位移只有 245／500 局在所有位移都終局（看門狗截斷 11–23%）；保留的局偏向較快結束的局，座位邊際（27.3／26.1／21.8／24.7%，同時區間下界只有 0.3 pp）只有參考價值。
